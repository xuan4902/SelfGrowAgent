# 数据来源与合规说明（对应赛事「数据合规」条款）

## 1. 核心声明

**本项目全部数据均为自建模拟数据（Simulated / Synthetic），不包含任何真实学生、教师或机构数据。**

产品运行所需的一切语料、题库、场景与演示数据，均由开发团队基于公开方法论（金字塔原理、
STAR、SBI、预期管理、复盘方法论等公开出版物与行业通用知识）自主编写并存入 `data/` 目录。

## 2. 数据类型与来源

| 数据类别 | 存放位置 | 内容 | 来源 |
|---|---|---|---|
| 能力框架 | `data/frameworks/managing_up.json` | 6 维度 × 5 级行为锚定、提升路径、演练 rubric | 自建（基于公开方法论梳理） |
| 测评题库 | `data/assessments/managing_up_questions.json` | 18 题情景选择题（难度分层）+ 标准答案与解析 | 自建情景模拟 |
| 情景副本 | `data/scenarios/managing_up_scenarios.json` | 4 个向上管理演练场景 + NPC 人设与台词 | 自建模拟职场情景 |
| 知识语料 | `data/knowledge/managing_up/*.md`（10 篇） | 金字塔汇报/STAR/SBI/预期管理等讲解 | 自建（基于公开方法论原创撰写） |
| 学习数据 | SQLite `data/selfgrow.db` | 测评/计划/学习记录/演练/复盘/学习者档案 | 运行时由用户与系统产生 |
| 图片/代码 | 仓库其余部分 | — | 开发团队原创 |

## 3. 运行时数据处理原则

1. **最小化**：仅采集完成任务所需的作答与反思文本，不采集任何身份信息；
   `learner_id` 由用户自拟（默认为 `learner_01` 等演示 ID），可与真实身份无关。
2. **本地优先**：默认全程本地 SQLite 存储，不依赖外部账号体系；RAG 检索发生在本地向量库。
3. **去标识化**：若后续接入真实学习者数据，需在接入层完成去标识化、脱敏与匿名化处理，
   并在通过数据合规评审后方可启用（当前版本不接入）。

## 4. 演示数据的合规性

- 自动演示模式（`--mode auto`）使用预置脚本作答，**不产生任何真实行为数据**，用于功能演示与录屏。
- 交互模式产生的是**演示性模拟作答**，仅用于验证产品能力闭环。
- 测试全部基于内存库（`:memory:`）或临时数据，不写入真实数据。

## 5. 接入真实数据的评审清单（如后续迭代）

若要接入真实学习者（尤其未成年人/学生）数据，必须完成：

- [ ] 数据合规评审与伦理审批
- [ ] 家长/监护人知情同意（涉未成年人）
- [ ] 去标识化 / 脱敏 / 匿名化技术方案
- [ ] 数据留存期限与删除机制
- [ ] 存储加密与访问控制
- [ ] 不采集敏感个人信息（健康、学籍、成绩等）
